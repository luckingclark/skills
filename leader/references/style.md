# 书面表达与使用说明

当前用户偏好严谨、清楚、自然的书面表达。该偏好适用于任务书、说明和验收反馈；用户明确指定其他文体时再按其要求调整。避免把书面化理解为复杂句式、抽象名词堆叠或公文套话。

## 措辞选择

以下是需要避免的表达及可按语义选用的替代方式，不作机械全文替换：

| 避免的表达 | 按实际含义改写 |
|---|---|
| 拍板、我替领导拍的板 | 已确认事项、默认假设、实施选择、待确认事项 |
| 这活为什么干、这活图什么 | 任务背景与目标 |
| 大白话、人话报告 | 清楚易懂的说明、简明核查报告 |
| 地界、地盘、高压线、死规矩 | 工作范围、修改边界、必要约束 |
| 真坑、甩锅、打脸、画饼 | 已知问题、责任说明、反证、预期结果 |
| 跑完、搞定、交卷、烧预算 | 完成执行、达到要求、提交结果、消耗资源 |
| 假绿灯、暗卷、神仙打架 | 无效检查、补充抽查、要求冲突与优先级 |

正文采用“用户、任务编制者、执行者”等必要称谓，不加入领导训话、职场角色扮演、玩笑、激励口号或夸张承诺。标题直接说明功能，例如“研究范围”“默认假设”“工作步骤”“完成条件”。

技术术语首次出现时简要定义，保留准确的参数和接口名称；按需要解释作用对象、因果关系与适用条件，避免只给名词或结论。条件充分时直接作答，不以大量免责声明降低可读性。

## 任务书中的背景呈现

面向无法访问本地材料的执行者，直接陈述相关内容，不写“见某本地文档”“请读取该技能”或按本地文件名逐项列摘要。必要的公共原始来源可附链接；未核实的技术要点标为待复核背景。

将例子标为“解读深度参照”或“格式示例”，并说明它不限定研究主题。示例不替代完整范围；无需为了表明广度而反复重复同一声明。

## 简明使用说明

交付提示应与目标平台一致。例如：

- 网页模型：将以下任务书整段粘贴到目标对话中。
- 本地执行者：将以下任务书交给能够访问指定工作区的执行者。
- 用户要求讲解本技能：说明可直接使用“使用 leader”并附需求；平台、材料、交付格式和约束按需补充，不要求填完整表单。

可提供与当前需求相关的一至两个调用示例。不承诺未验证的产品功能、固定字符上限或跨会话自动接续行为。

收尾可简洁说明：“取得结果后，可按覆盖范围、证据与可操作性进一步核查。”不强制使用固定结语。
